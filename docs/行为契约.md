# WinsRehab 行为契约

**更新日期**：2026-11-18

**定位**：记录**已经实现、后续不得无意改坏**的行为。它不是需求池，也不是路线图；未实现的能力统一写在 [开发计划](./开发计划.md)。

> 修改契约内的行为，必须同时更新本文件与对应测试；只改代码不改契约，视为回归。
> 这里的“必须 / 不得”是回归判据，不是对未来的承诺。

---

## 1. 任务与计划

### 1.1 状态模型

任务状态：

| 状态 | 含义 | 当前是否可写 |
|------|------|--------------|
| `pending` | 待完成，唯一可执行状态 | 生成任务时写入 |
| `completed` | 患者完成；未来也用于审核通过 | `completeTask` |
| `skipped` | 患者主动跳过，不计完成 | `skipTask` |
| `waiting_review` | 已提交视频、等待医生审核 | 仅常量预留，业务未接 |
| `rejected` | 医生驳回、可重录 | 仅常量预留，业务未接 |

计划状态：`draft → active → completed / cancelled`。当前创建计划时会写入 `draft` 或 `active`；`completed` / `cancelled` 在 Repository 有方法，但尚无页面调用。

### 1.2 完成与跳过

- 只有 `pending` 任务可以被“完成”或“跳过”。
- 完成/跳过必须走 `TaskExecutionRepository.completeTask(instanceId, today)` / `skipTask(instanceId, today)`，不得在 Fragment 里直接改状态。
- 两个动作在 `db.withTransaction` 内完成：先更新 `TaskInstance.status` 与 `completedAt`，再重算并写回 `RehabPlan.progress`。
- 重复执行同一任务必须幂等：已是 `completed` / `skipped` / `waiting_review` / `rejected` 时直接忽略，不改状态、不重复重算。
- 任务或计划脏数据（找不到模板/计划、日期非法）只记日志并跳过重算，不阻断状态更新。
- 跳过只写 `completedAt` 供审计，**不计入任何完成数**。

### 1.3 计划进度

```
progress = 已完成数 ÷ 截至今天的应完成数 × 100（向下取整，限制 0–100）
```

- 应完成数为 0 时进度记 0，不出现除零，也不显示 100。
- 已完成数只统计 `status = completed` 且 `scheduledDate` 落在 `[计划开始日, min(今天, 计划结束日)]` 的实例。
- 分子与分母必须使用同一窗口；窗口外的历史完成实例不计入分子。
- 计划结束日早于今天时，应完成数只算到结束日。
- 进度只在“完成/跳过”业务动作的事务内重算；新建计划初始进度为 0，生成任务不触发重算。

### 1.4 应完成数

- 只依据计划开始日、结束日与每个任务的频率规则推算，**不得**用数据库里实际生成的任务条数代替。
- 窗口为 `[计划开始日, min(今天, 计划结束日)]`，含两端，逐日判断频率。
- `daily`：窗口内每天算 1 次。
- `weekly`：`frequencyDetail` 形如 `"1,3,5"`，1=周一、7=周日，只算命中的星期。
- `interval`：从计划开始日算起，`(日期 - 开始日) % 间隔 == 0`；不依赖上次生成日期，中途漏登录不会漂移。
- 窗口超过 3660 天按 3660 天截断，避免脏数据造成超长循环。
- 漏生成不会缩小应完成数，因此计划进度不会因患者漏登录而虚高。

### 1.5 生成时间窗

- 仅当 `计划开始日 ≤ 目标日期 ≤ 计划结束日` 才生成；窗口判断先于频率判断。
- 开始日、结束日当天都算在窗内；多个计划各自独立判断。
- 登录触发与 `PtMainActivity.onResume` 触发受同一时间窗约束。
- 同一 `(任务, 患者, 日期)` 最多一条实例：业务层 `isInstanceExists` 预检 + 数据库唯一索引 + `OnConflictStrategy.IGNORE` 兜底。
- 只生成当天，不补生成历史任务。

### 1.6 计划起止日期

- 新建/保存计划时，开始日期不得早于今天。
- 结束日期 = 开始日期 + 周期天数 - 1；7 天计划覆盖 7 个自然日。
- 校验只作用于新建/保存，不影响历史计划读取。
- 存草稿与直接激活走同一套校验。

## 2. 患者康复页

页面实现：`app/src/main/java/com/example/winsrehab/ui/main/patient/main/pt_rehabFragment.kt`；数据由 `PtRehabViewModel` 提供。

### 2.1 今日任务列表

- 只展示当前患者、当天、数据库中真实存在的 `TaskInstance`，不出现写死的示例任务。
- 每条展示任务名称、建议时长、优先级，并按状态显示对应徽标：待完成 / 已完成 / 已跳过 / 待审核 / 已驳回。
- 当天无任务时显示空态；今日进度显示 `0/0`、0%，页面不崩。
- `waiting_review` / `rejected` 任务仍展示，但不出现“开始”入口。

### 2.2 完成 / 跳过交互

- 只有 `pending` 任务有“开始”入口；点击弹出“完成 / 跳过 / 取消”三选一对话框。
- 选“完成” → `completed`；选“跳过” → `skipped`；选“取消”或关闭对话框 → 不产生任何数据变更。
- 操作成功后任务条目立即切换状态，入口消失；已完成/已跳过任务不再弹确认框。
- 首次进入与操作后刷新必须使用同一套字段与视觉口径。

### 2.3 今日进度

- 显示真实“已完成数 / 今日任务总数”和百分比，横向 `ProgressBar` 按比例填充。
- 总数为 0 时显示 `0/0`、0%，不出现除零或空白。
- 百分比与列表中的完成条数必须同源一致；禁止用固定示例值（如写死 2/4、50%）。
- 当前实现是“文字 + 横向进度条”，不存在以环形图作为唯一数据载体的实现。

### 2.4 本周柱状图

- 固定按周一至周日七天展示，每天显示真实“完成数 / 总数”。
- 柱高按完成比例绘制；总数为 0 的当天柱高为 0。
- 标记今天；周日属于本周最后一天，不得被算进下一周。
- 柱状图七天之和必须等于底部“本周完成”卡片的完成数与总数。

### 2.5 底部统计卡

- “本周完成”接真实周数据，显示 `本周完成数/本周总数`。
- “累计训练”“连续打卡”当前没有数据来源，统一显示占位符 `--`，不得伪造“28 天”“7 天”等数值。

### 2.6 刷新与错误

- 完成/跳过成功后，今日列表、今日进度、本周柱状图、本周完成卡自动刷新。
- 页面进入与恢复到 `STARTED` 时重新订阅，重新计算“今天”和本周区间；跨零点/跨周不沿用旧数据。
- 无法解析患者标识时进入错误态并提供“重试”，不查询空 id，也不把取参失败显示成“今天没有任务”。

### 2.7 首页与康复中心同源

- 患者首页与康复中心共用 `PtMainActivity` 作用域的同一个 `PtRehabViewModel`（两处均 `by activityViewModels()`），只订阅一次周数据。
- 两处使用同一自然周（周一至周日）、同一完成算法；跳过不计入完成。
- 允许因刷新时机不同出现短暂不一致，但同一时刻渲染出的数字必须相同。
- 空态/占位在两处保持一致，不得一处占位、另一处显示旧值。

## 3. 界面基线

### 3.1 取值表

- 颜色、字号、间距、圆角、阴影只能从 `app/src/main/res/values/` 下的语义 token 取，不在布局里写裸色值或档位外裸数值。
- 字号 6 档：11 / 12 / 14 / 16 / 20 / 24sp。
- 间距以 4dp 为基准，主用 4 / 8 / 12 / 16 / 24 / 32dp；48dp 仅用于列表/页面底部留白。
- 圆角 3 档：8 / 12 / 16dp；阴影 2 档：0 / 1dp。
- 颜色使用语义名（如 `on_surface`、`danger`、`status_pending`），不直接写 `#RRGGBB`；对比度档位以 `colors.xml` 注释为准。

### 3.2 双端主题

- 医生端蓝色、患者端绿色，均继承同一个 Material 浅色基础主题。
- 两端只允许主题色不同；字号、间距、圆角、阴影与组件形态保持一致。
- 基础主题锁定浅色，不跟随系统深色模式；要支持夜间模式必须作为独立变更，同时交付完整夜间取值表。
- 页面不得自行覆盖成其它主题。

### 3.3 组件与状态映射

- 统一按钮覆盖主按钮、次按钮、危险按钮、文字按钮，支持尺寸档与禁用态。
- 统一输入框支持标签、必填标记、错误文案、辅助文本。
- 统一卡片覆盖标准卡片、可点击卡片、带状态条卡片。
- 任务五态与计划四态的“文案 + 语义色”只能由 `TaskStatusStyle` / `StatusBadge` 提供，不得出现第二套映射。
- 未登记状态必须显式落到“未知状态”，不得静默套用某个合法状态的样式。

### 3.4 三态与占位

- 每个数据驱动界面必须有加载态、空态、错误态。
- 空态说明“当前没有数据”，不是报错；错误态显示原因并提供重试。
- 加载态不显示旧数据残留，也不显示空态。
- 无数据来源的统计项统一显示 `--`；占位、空态、错误态文案统一由 `UiTexts` 提供，页面不各自持有副本。

### 3.5 “即将开放”入口

- 业务能力尚未实现的入口必须标注“即将开放”并置灰，且保留在布局中。
- 置灰后点击不跳转、不写数据、不弹提示；重复点击结果相同。
- 能力实现后，同一入口应能在不改布局结构的前提下恢复响应。
- 不得把未实现入口直接删掉来“让界面干净”。

### 3.6 资源完整性

- 不被任何布局或代码引用的图片、布局、字符串、主题样式必须删除。
- 声明了但零使用的 UI 框架开关/依赖必须移除。
- 清单中不得保留指向不存在类的组件声明。

## 4. 页面接线

### 4.1 业务数据必须有真实来源

- 界面上的计数、比率、名称、状态、时间、进度都必须能追溯到数据来源。
- 不得用布局默认值、示例文本、硬编码数字充当业务数据。
- 没有写入路径的统计项显示统一占位 `--`，不得临时编造数值。
- 标题、说明、引导等静态文案可以写字面量；跨页面复用或需按状态映射的文案必须统一管理。

### 4.2 患者字段

- 患者姓名、诊断、康复阶段、康复进度取档案真实字段。
- 字段为空时显示统一占位（如“未设置”），不得用布局默认值冒充。
- 同一患者的康复阶段在各处展示一致。

### 4.3 医生端患者总数

- 医生首页“管理患者数”、患者管理页总数、医生“我的”页面患者数必须同源同口径。
- 医生“我的”页面自行观察同一查询，不得依赖其它页面通过导航参数传入计数。
- 新增患者后三处同时 +1；允许刷新时机导致的短暂不一致，完成一次刷新后必须一致。

### 4.4 页面可达性

- 每个已实现页面至少有一条用户可达入口，不得“代码存在但没有任何导航/跳转引用”。
- 同一页面允许多个入口，但每个入口都必须携带页面运行所需参数。
- 入口缺参数导致空数据或直接退出的，视为入口未接入完成。

### 4.5 入口去向完整

- 每个可交互入口必须有明确去向：进入已实现页面，或按“即将开放”置灰。
- 不得存在“看起来可点、点了既不跳转也不改变状态”的第三态。
- 仅展示、不承担跳转的文字不得呈现为可点击形态。

### 4.6 跨页面参数解析

- 账号/工号统一按“导航参数优先、宿主页面传值兜底”解析，只保留这一条链。
- 两条来源都取不到时，进入明确的空态/错误态并说明原因，不得用空串继续查询后静默显示“无数据”。
- 新增入口从建立时就沿用同一解析链，不复制旧的“取不到给空串”写法。

### 4.7 患者申请到患者名单

- 链路：患者提交绑定申请 → 医生首页看到待办 → 医生确认/拒绝 → 患者名单与计数更新。
- 确认后：该申请从医生首页最新申请与待办计数中消失；患者出现在患者管理列表并计入总数。
- 拒绝后：申请与计数消失，患者不进入名单，总数不变。
- 无待处理申请时显示空态，计数为 0（不是占位符）。

## 5. 验证与维护

### 5.1 现有验证

| 层级 | 范围 | 当前规模 |
|------|------|----------|
| JVM 单测 | 日期/频率/进度/状态映射/UI 文案与结构契约 | 105 个 `@Test` |
| 界面自动化 | 登录、导航、患者康复页、医生页、绑定流程 | 27 个 `@Test` |
| Lint | `lintDebug` | 0 error（warning 未清零） |

常用命令：

```bash
./gradlew.bat :app:testDebugUnitTest --rerun-tasks
./gradlew.bat :app:lintDebug
./gradlew.bat :app:connectedDebugAndroidTest "-Pandroid.injected.device.serial=emulator-5554"
```

界面测试跑前先唤醒模拟器；机器负载高时偶发登录后等待 `doctorHomeRoot` 超时，属等待时间不足，重跑即可。

### 5.2 修改规则

1. 先判断改动是否触碰本契约；触碰则先改契约与测试，再改实现。
2. 纯逻辑优先补 JVM 单测；界面行为优先补 `androidTest`，无法自动化的写入手工验收步骤。
3. 契约只记录已实现行为；新能力落地后再补进来，不把计划写成契约。
4. 文档中的数字、类名、路径必须能从当前代码复现；不确定就写“以代码为准”，不要猜。
