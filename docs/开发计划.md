# WinsRehab 开发计划（4 周冲刺）

**版本**：v2  
**制定日期**：2026-11-09  
**周期**：4 周，共约 60 小时  
**产品定位**：康复闭环为主，心理放松为辅  
**运行模式**：本地优先，单设备演示  
**替代**：2026-09-07 的 10 天 MVP 计划（旧文档已删除，历史见 git）  
**进度基线**：代码停在 2026-09-07，完成度约 45%；本计划从当前代码继续

## 0. 本月的“完成”定义

月末能在同一台设备上连续演示：

1. 医生创建并激活康复计划（含 daily / weekly / interval 任务）
2. 患者登录，看到今天应做的任务和环形进度
3. 患者完成/跳过任务，状态落库
4. 患者录制训练视频，视频入库，任务进入待审核
5. 医生看到待审核视频，播放并通过/驳回，填写评语
6. 患者看到审核结果；驳回可重录
7. 医生能看到患者今日完成数和计划进度
8. 患者端“放松中心”可玩五子棋、可后台播放音乐

**本月明确不做**：

- 真实后端、跨设备同步
- 自定义 MediaCodec 二次转码（先用 CameraX 质量档位）
- 完整反馈聊天/消息中心
- 计划调整的完整编辑 UI（保留 `PlanAdjustment` 数据结构，第二个月做）

> 本地模式的现实：医生和患者必须在同一台设备/同一个数据库切账号演示。两台设备不会同步，这是本地优先的必然结果，不是 bug。

把“完成”升级成“录视频提交 → 医生审核 → 患者看结果”。

**验收**：录 30 秒，文件可播放，体积可接受。

### Day 3（3h）：视频入库与状态流转

- `PtRehabVideoDao / Repository`：插入/查询/更新审核状态
- `TaskExecutionRepository.submitVideo(instanceId, file)`：
  - 插入 `PtRehabVideo`
  - `TaskInstance.status = waiting_review`、`videoId`
- 患者任务项显示“待审核”，可点击播放

**验收**：录完回到列表，任务变“待审核”；重启后仍在。

### Day 4（3h）：医生待审核

- `ui/main/doctor/review/PendingReviewActivity.kt`
- `ReviewAdapter` + `item_review.xml`：患者名、任务名、时间、状态
- 查询：医生所有 active 患者的 `pending` 视频
- 点击进 `ReviewDetailActivity`：播放 + 通过/驳回 + 评语

**验收**：医生能看到待审核列表并播放。

### Day 5（3h）：审核结果回流

- `TaskExecutionRepository.reviewVideo(videoId, approved, comment)`：事务更新视频 + 任务
  - 通过：`TaskInstance.completed`，`PtRehabVideo.approved`

**验收**：通过和驳回各走一遍；驳回后重录，状态回到 `waiting_review`。

### Week 2 验收脚本

1. 患者录 30 秒视频，任务变待审核

## 7. 关键设计约束

### 7.1 状态机只有一个写入口

```
TaskInstance: pending → completed / skipped
              pending → waiting_review → completed（审核通过）
                                      → rejected（审核驳回）→ pending（重录）
RehabPlan:    draft → active → completed / cancelled
PtRehabVideo: local → queued → uploaded → pending_review → approved / rejected
```

UI 只发意图，所有 `status` 变更走 `TaskExecutionRepository`。不要在 Fragment 里 `copy(status = ...)`。

### 7.2 生成是纯函数

生成结果只依赖 `(task, planStartDate, date)`，不依赖 `lastScheduledDate`。这样可单测、可重放，患者漏几天也不会让 interval 节奏漂移。

**不要补生成历史任务**。漏了就是漏了，补生成会让患者把昨天的任务算到今天，数据失真。

### 7.3 计划进度按“应完成”算

`progress = 已完成 / 计划窗口内截至今天的应完成任务数`，不是“已完成 / 已生成实例数”。否则计划最后几天进度会突然跳变。

### 7.4 上传先抽象，不写死本地

```kotlin
interface VideoUploader {
    suspend fun upload(video: PtRehabVideo): Result<String>
}

class LocalVideoUploader : VideoUploader   // 现在
class HttpVideoUploader : VideoUploader    // 后端阶段
```

现在 `LocalVideoUploader` 把文件放进 `filesDir/uploads` 并标记 `uploaded`；医生端读同一个路径。以后换实现，不动 UI 和 Repository。

### 7.5 放松模块独立

```
ui/relax/
  RelaxCenterActivity.kt
  music/  PlaybackService.kt, MusicPlayerActivity.kt
  gomoku/ GomokuBoardView.kt, GomokuGame.kt, GomokuActivity.kt
```

不要把这些类放进康复主域。这样代码看着顺眼，面试也能讲“模块边界”。
