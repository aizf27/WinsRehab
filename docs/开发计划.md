## 🎯 MVP目标

### 核心闭环必须跑通
```
医生创建计划 
  → 系统自动生成今日任务 
  → 患者看到任务并执行 
  → 患者录制视频上传 
  → 医生审核视频给点评 
  → 患者查看审核结果
```

### MVP验收标准
1. ✅ 医生能为患者制定康复计划（包含多个任务）
2. ⏳ 患者登录后自动生成今日任务（根据频率规则）
3. ⏳ 患者能看到今日任务列表，显示任务详情
4. ⏳ 患者能录制视频、添加说明、上传
5. ⏳ 医生能看到待审核视频队列
6. ⏳ 医生能播放视频、填写点评、提交审核
7. ⏳ 患者能查看审核结果和医生建议

### 第1阶段：任务生成逻辑（Day 1-2）

**目标**：实现任务自动生成，让患者能看到今日任务

#### Day 1：实现任务生成算法

**任务清单**：
- [ ] 在`TaskInstanceRepository`创建`generateDailyTasks(patientId, date)`方法
  - 获取患者的所有活跃康复计划（status = 'active'）
  - 遍历计划中的所有TrainingTask
  - 根据频率规则判断今天是否应生成任务
  - 检查是否已存在（去重：patientId + taskId + date）
  - 生成TaskInstance并批量插入
- [ ] 实现频率判断逻辑：
  - `daily` - 每天都生成
  - `weekly` - 解析frequencyDetail（如"1,3,5"），判断今天星期几
  - `interval` - 解析frequencyDetail（如"2"），根据上次生成日期计算
- [ ] 创建`TaskGenerationService`工具类
  - `shouldGenerateToday(task: TrainingTask, date: String): Boolean`
  - `getDayOfWeek(date: String): Int` - 返回1-7（周一到周日）
  - `calculateNextDate(lastDate: String, interval: Int): String`
- [ ] 编写单元测试（测试各种频率规则）

**产出**：任务生成算法完成，单元测试通过

## ⚠️ 风险与应对

### 风险1：CameraX集成复杂度高
- **概率**：中
- **影响**：可能延迟1-2天
- **应对**：备选方案使用系统相机Intent（更简单但功能受限）

### 风险2：视频文件过大
- **概率**：高
- **影响**：加载慢、存储空间不足
- **应对**：
  - 录制时限制分辨率720p
  - 限制时长5分钟
  - 限制码率降低文件大小

### 风险3：任务生成逻辑边界情况复杂
- **概率**：中
- **影响**：某些频率规则生成不正确
- **应对**：Day 1多写单元测试覆盖各种场景

### 风险4：时间不足
- **概率**：中
- **影响**：10天内无法完成所有功能
- **应对**：
  - 优先级调整：Day 1-6必须完成
  - Day 7-9可压缩（审核功能简化）
  - Day 10弹性调整
