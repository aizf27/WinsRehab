# WinsRehab 项目架构总览

**更新日期**：2026-09-07  
**项目版本**：v0.5-dev  
**数据库版本**：7

---

## 项目定位

**医患双端康复管理系统**，实现康复计划制定、任务分配、进度追踪和视频指导的完整闭环。

---

## 技术栈

- **语言**：Kotlin
- **架构**：MVVM + Repository
- **数据库**：Room Database（版本7，9张表）
- **异步**：Coroutines + Flow
- **UI**：ViewBinding + Navigation Component
- **最低SDK**：26（Android 8.0）

---

## 架构分层

```
UI层（Activity/Fragment + ViewModel）
    ↓
Repository层（业务逻辑封装）
    ↓
DAO层（Room数据库访问）
    ↓
Entity层（数据实体）
```

---

## 核心数据模型（9张表）

### 用户表（2张）
- **Doctor**：医生工号、职称、科室、管理患者数
- **Patient**：账号、绑定医生、bindingStatus（unbound/pending/active/rejected）

### 康复计划核心（4张）
- **RehabPlan**：康复计划（状态：draft→active→completed/cancelled）
- **TrainingTask**：训练任务模板（频率规则：daily/weekly/interval）
- **TaskInstance**：任务实例（由模板生成，患者实际操作对象）
- **PlanAdjustment**：计划调整记录（追踪医生调整历史）

### 辅助功能（3张）
- **PtRehabVideo**：患者康复视频
- **DemoVideo**：示范视频库
- **DoctorTask**：医生待办事项

## 应用流程

### 启动入口
```
SelectLogActivity
  ├─ 医生登录 → DtLogActivity → DtHomeActivity
  └─ 患者登录 → PtLogActivity → 绑定流程 → PtMainActivity
```

### 患者绑定流程
```
注册/登录 → 检查bindingStatus
  ├─ unbound：输入医生工号发送绑定申请
  ├─ pending：等待医生确认（WaitingBindingActivity）
  ├─ active：进入主界面
  └─ rejected：重新绑定
```

### 医生端（DtHomeActivity）
- **dt_homeFragment**：首页概览
- **dt_pt_manageFragment**：患者管理
- **dt_info_Fragment**：个人信息
- **关键功能**：
  - PatientApplicationActivity：处理患者绑定申请
  - CreateRehabPlanActivity：创建康复计划

### 患者端（PtMainActivity）
- **pt_homeFragment**：首页（今日任务、进度）
- **pt_rehabFragment**：康复训练
- **pt_infoFragment**：个人信息
- **辅助功能**：
  - TrainingVideoActivity：训练视频列表
  - PsychologyActivity：心理咨询助手

## 关键技术点

### 1. 任务生成机制
- **模板**：TrainingTask定义任务类型、频率规则
- **实例**：系统根据频率规则生成TaskInstance
- **频率类型**：daily（每天）、weekly（特定星期几）、interval（间隔N天）

### 2. 状态管理
- **绑定状态**：unbound → pending → active/rejected
- **计划状态**：draft → active → completed/cancelled
- **任务状态**：pending → completed/skipped/waiting_review

### 3. 响应式数据流
- 大量使用Flow实现UI自动响应数据变化
- ViewModel通过LiveData/StateFlow管理UI状态

## 架构风险提示

1. **数据库迁移**：当前使用`fallbackToDestructiveMigration`，发布前需编写Migration脚本
2. **冗余字段同步**：Patient表的统计字段需定时更新机制
3. **网络层缺失**：当前只有本地数据库，后续需补充API层
4. **UI混合方案**：同时使用ViewBinding和Compose，需统一技术栈
