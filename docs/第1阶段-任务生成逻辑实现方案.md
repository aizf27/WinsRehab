# 第1阶段：任务生成逻辑实现方案

**制定日期**：2026-09-07  
**预计时间**：2个工作日  
**核心目标**：实现任务自动生成，让患者登录后能看到今日任务

---

## 📋 阶段概述

### 业务需求
医生创建康复计划时定义了任务模板（TrainingTask），系统需要根据这些模板的频率规则，自动为患者生成每日任务实例（TaskInstance）。

### 核心流程
```
患者登录 
  → 触发任务生成 
  → 读取该患者的活跃康复计划 
  → 遍历计划中的任务模板 
  → 根据频率规则判断今天是否生成 
  → 检查去重 
  → 批量插入TaskInstance
```

### 技术要点
- **频率规则解析**：daily（每天）、weekly（特定星期几）、interval（间隔N天）
- **去重机制**：同一任务+同一日期不重复生成
- **日期计算**：星期几判断、日期间隔计算
- **批量操作**：减少数据库IO次数

### 阶段1.1：创建频率判断工具类（3小时）

**目标**：封装频率判断逻辑，方便测试和复用

**创建文件**：`app/src/main/java/com/example/winsrehab/utils/TaskGenerationHelper.kt`

**核心方法设计**：

```kotlin
object TaskGenerationHelper {
    // 判断任务今天是否应该生成
    fun shouldGenerateToday(task: TrainingTask, date: String): Boolean
    
    // 获取日期是星期几（1=周一，7=周日）
    fun getDayOfWeek(date: String): Int
    
    // 解析weekly的频率详情（"1,3,5" → [1,3,5]）
    fun parseWeeklyDays(frequencyDetail: String): List<Int>
    
    // 计算间隔天数是否满足
    fun shouldGenerateByInterval(lastDate: String, targetDate: String, interval: Int): Boolean
    
    // 日期格式化工具
    fun formatDate(timeMillis: Long): String  // 转为yyyy-MM-dd
    fun parseDate(dateStr: String): Long      // 转为时间戳
}
```

**实现思路**：
1. **daily频率**：直接返回true
2. **weekly频率**：
   - 解析frequencyDetail（如"1,3,5"）
   - 计算targetDate是星期几
   - 判断是否在列表中
3. **interval频率**：
   - 解析frequencyDetail获取间隔天数
   - 需要查询上一次生成日期（TaskInstance表中该任务最后一条记录）
   - 计算日期差是否≥间隔天数

**边界处理**：
- frequencyDetail为空的情况
- 日期格式异常的兜底
- 周日的处理（Calendar.SUNDAY=1需转为7）

### 阶段1.2：扩展DAO查询方法（1小时）

**目标**：补充任务生成所需的数据库查询方法

**修改文件**：
- `app/src/main/java/com/example/winsrehab/data/dao/RehabPlanDao.kt`
- `app/src/main/java/com/example/winsrehab/data/dao/TaskInstanceDao.kt`

**需要的新方法**：

**RehabPlanDao**：
```kotlin
// 获取患者的活跃计划（一次性查询，用于生成任务）
@Query("SELECT * FROM rehab_plan WHERE patientId = :patientId AND status = 'active'")
suspend fun getActivePlansByPatientOnce(patientId: String): List<RehabPlan>
```

**TaskInstanceDao**：
```kotlin
// 检查任务实例是否已存在（去重）
@Query("SELECT COUNT(*) FROM task_instance WHERE taskId = :taskId AND patientId = :patientId AND scheduledDate = :date")
suspend fun isInstanceExists(taskId: Long, patientId: String, date: String): Int

// 获取任务的最后生成日期（用于interval频率）
@Query("SELECT MAX(scheduledDate) FROM task_instance WHERE taskId = :taskId AND patientId = :patientId")
suspend fun getLastScheduledDate(taskId: Long, patientId: String): String?
```

**为什么需要这些方法**：
- `getActivePlansByPatientOnce`：生成任务时需要一次性获取所有活跃计划，不用Flow
- `isInstanceExists`：防止重复生成（用户可能多次登录或刷新）
- `getLastScheduledDate`：interval频率需要知道上次什么时候生成的

### 阶段1.3：实现Repository层生成逻辑（4小时）

**目标**：在Repository层实现任务生成的核心业务逻辑

**修改文件**：`app/src/main/java/com/example/winsrehab/data/repository/TaskInstanceRepository.kt`

**核心方法**：
```kotlin
/**
 * 为患者生成今日任务
 * @param patientId 患者ID
 * @param date 日期（yyyy-MM-dd格式）
 * @return 生成的任务实例数量
 */
suspend fun generateDailyTasks(patientId: String, date: String): Int
```

**实现步骤**：

1. **获取活跃计划**
   - 调用`rehabPlanDao.getActivePlansByPatientOnce(patientId)`
   - 如果没有活跃计划，直接返回0

2. **遍历计划的任务模板**
   - 对每个plan，调用`trainingTaskDao.getTasksByPlanOnce(planId)`
   - 获取该计划的所有TrainingTask

3. **逐个判断是否生成**
   - 调用`TaskGenerationHelper.shouldGenerateToday(task, date)`
   - 如果返回false，跳过

4. **去重检查**
   - 调用`taskInstanceDao.isInstanceExists(taskId, patientId, date)`
   - 如果已存在（返回>0），跳过

5. **构建TaskInstance对象**
   - instanceId自动生成（传0）
   - taskId从task中获取
   - patientId传入
   - scheduledDate传入date
   - status默认"pending"
   - 其他字段默认值

6. **批量插入**
   - 将所有待生成的TaskInstance收集到List
   - 调用`taskInstanceDao.insertInstances(list)`一次性插入
   - 返回生成数量

**interval频率的特殊处理**：
- 调用`taskInstanceDao.getLastScheduledDate(taskId, patientId)`
- 如果lastDate为null（首次生成），直接生成
- 如果不为null，调用`TaskGenerationHelper.shouldGenerateByInterval(lastDate, date, interval)`

**日志记录**：
```kotlin
Log.i("TaskInstanceRepository", "开始生成任务: patientId=$patientId, date=$date")
Log.i("TaskInstanceRepository", "找到${activePlans.size}个活跃计划")
Log.i("TaskInstanceRepository", "计划${plan.planName}有${tasks.size}个任务模板")
Log.i("TaskInstanceRepository", "任务${task.taskName}满足频率规则，准备生成")

```

### 阶段1.4：集成到登录流程（2小时）

**目标**：患者登录成功后自动触发任务生成

**修改文件**：`app/src/main/java/com/example/winsrehab/ui/main/patient/login/PtLogVM.kt`

**集成位置**：
- 在登录成功的回调中，获取当前日期
- 调用`taskInstanceRepository.generateDailyTasks(patientId, today)`
- 添加协程处理和错误捕获

**代码思路**：
```kotlin
viewModelScope.launch {
    try {
        val today = SimpleDateFormat("yyyy-MM-dd", Locale.getDefault()).format(Date())
        val count = taskInstanceRepository.generateDailyTasks(patientId, today)
```

**为什么不阻断登录**：
- 任务生成是辅助功能，失败不应影响登录
- 用户进入主界面后可以手动刷新
- 后续在onResume也会再次尝试

### 阶段1.5：增加刷新触发点（1小时）

**目标**：在患者主界面恢复时也触发任务生成（防止中途激活新计划）

**修改文件**：`app/src/main/java/com/example/winsrehab/ui/main/patient/main/PtMainActivity.kt`

**实现方式**：
- 在`onResume()`生命周期方法中触发
- 从SharedPreferences获取当前登录的patientId
- 获取当前日期
- 调用生成方法

**注意事项**：
- onResume可能频繁调用（切换应用、锁屏等）
- 需要优化：如果今天已经生成过，isInstanceExists会自动去重
- 性能影响较小，因为有去重机制

**代码思路**：
```kotlin
override fun onResume() {
    super.onResume()
    
    lifecycleScope.launch {
        try {
            val patientId = getPatientId() // 从SP读取
            val today = getCurrentDate()
            taskInstanceRepository.generateDailyTasks(patientId, today)
        } catch (e: Exception) {
            Log.e("PtMainActivity", "刷新任务失败", e)
        }
    }
}
```

### 阶段1.7：异常处理和优化（1小时）

**目标**：增强健壮性，处理边界情况

**异常情况处理**：

1. **日期格式异常**
   - 捕获SimpleDateFormat的异常
   - 使用默认日期或跳过

2. **frequencyDetail格式错误**
   - weekly的"1,3,5"如果写成"1-3-5"或"abc"
   - 解析失败返回空列表，该任务不生成
   - 添加日志记录格式错误

3. **数据库查询为空**
   - 活跃计划为空：正常返回0
   - 计划的任务为空：跳过该计划
   - lastDate为null：interval首次生成

4. **并发问题**
   - 登录和onResume可能同时触发
   - 依赖isInstanceExists的去重机制
   - 数据库INSERT有UNIQUE约束保底

**性能优化**：

1. **批量插入**
   - 收集所有待生成的TaskInstance
   - 一次性insertInstances，而不是逐个insert

2. **减少查询**
   - 一次性获取所有活跃计划
   - 一次性获取计划的所有任务

3. **索引利用**
   - TaskInstance表已有索引：(patientId, scheduledDate)
   - 去重查询会走索引

**日志完善**：

## 🔍 关键技术点

### 日期计算
```kotlin
// 获取星期几
val calendar = Calendar.getInstance()
calendar.time = dateFormat.parse(date)
val dayOfWeek = calendar.get(Calendar.DAY_OF_WEEK)
// 注意：Calendar.SUNDAY=1，需转换为1-7（周一到周日）
val normalizedDay = if (dayOfWeek == 1) 7 else dayOfWeek - 1
```

### 日期间隔计算
```kotlin
val lastTime = dateFormat.parse(lastDate).time
val targetTime = dateFormat.parse(targetDate).time
val daysDiff = ((targetTime - lastTime) / (1000 * 60 * 60 * 24)).toInt()
return daysDiff >= interval
```

### 批量插入
```kotlin
@Dao
interface TaskInstanceDao {
    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertInstances(instances: List<TaskInstance>): List<Long>
}
```

## 🚨 风险点

### 风险1：interval频率首次生成时机
**问题**：interval任务没有lastDate，首次应该在什么时候生成？  
**方案**：lastDate为null时，直接生成（视为满足条件）

### 风险2：跨月或跨年的日期计算
**问题**：SimpleDateFormat可能出现时区问题  
**方案**：统一使用`Locale.getDefault()`和UTC时区

### 风险3：任务生成失败影响登录
**问题**：生成逻辑抛异常导致登录卡住  
**方案**：用try-catch包裹，失败只记录日志，不阻断登录

### 风险4：数据库并发写入
**问题**：登录和onResume同时触发生成  
**方案**：
- isInstanceExists去重
- INSERT使用OnConflictStrategy.IGNORE
- 添加数据库UNIQUE约束
