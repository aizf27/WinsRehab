## 📋 项目定位

WinsRehab是一个**医患协作的康复管理闭环系统**，通过数字化手段提升康复训练的效率和效果。

### 核心价值
- **医生端**：高效管理患者，制定个性化康复计划，实时监控康复进度
- **患者端**：清晰的训练指导，及时的医生反馈，持续的心理支持
- **闭环管理**：诊断 → 计划 → 执行 → 反馈 → 调整 → 康复

### 目标用户
- **医生**：康复科医生、理疗师
- **患者**：需要康复训练的患者（脑卒中、骨折、运动损伤等）

## 🏗️ 技术架构

### 技术栈
- **开发语言**：Kotlin
- **架构模式**：MVVM + Repository
- **数据库**：Room Database（版本7，9张表）
- **异步处理**：Kotlin Coroutines + Flow
- **UI框架**：ViewBinding + Navigation Component
- **AI集成**：DeepSeek API（心理助手）
- **最低SDK**：26（Android 8.0）

### 架构分层
```
UI层（Activity/Fragment + ViewModel）
    ↓
Repository层（业务逻辑封装）
    ↓
DAO层（Room数据库访问）
    ↓
Entity层（数据实体）
```

## 📊 数据模型（9张表）

### 用户表（2张）
- **Doctor** - 医生信息（doctorCode, name, title, department, hospital等）
- **Patient** - 患者信息（patientId, doctorCode, bindingStatus, diagnosis等）

### 康复计划核心（4张）
- **RehabPlan** - 康复计划（planName, goal, startDate, endDate, status, progress）
  - 状态：draft（草稿）→ active（进行中）→ completed/cancelled
- **TrainingTask** - 训练任务模板（taskName, frequency, frequencyDetail, suggestedDuration）
  - 频率类型：daily/weekly/interval
- **TaskInstance** - 任务实例（scheduledDate, status, completedAt, videoId）
  - 由TrainingTask根据频率规则生成，患者实际操作对象
- **PlanAdjustment** - 计划调整记录（adjustmentType, adjustmentDetail, reason）

### 辅助功能（3张）
- **PtRehabVideo** - 患者康复视频（videoUrl, uploadDate, description）
- **DemoVideo** - 示范视频库（title, videoUrl, category, difficulty）
- **DoctorTask** - 医生待办事项（taskType, patientId, status）

## 🔄 核心业务流程

### 完整康复闭环
```
1. 患者注册并绑定医生（输入医生工号）
   ↓
2. 医生确认接收患者
   ↓
3. 医生诊断并制定康复计划（包含多个训练任务）
   ↓
4. 系统生成每日训练任务（根据频率规则）
   ↓
5. 患者查看今日任务并执行训练
   ↓
6. 患者录制训练视频并上传
   ↓
7. 医生审核视频并给出点评
   ↓
8. 患者查看审核结果和医生建议
   ↓
9. 患者发送反馈给医生
   ↓
10. 医生根据反馈调整康复计划
    ↓
11. 循环执行直至康复目标达成
```

### 关键机制说明

#### 1. 医患绑定机制
- **患者主动绑定**：首次登录时输入医生工号
- **医生确认接收**：医生端收到"新患者申请"通知，确认后建立医患关系
- **绑定状态**：unbound（未绑定）→ pending（待确认）→ active（已确认）/ rejected（已拒绝）

#### 2. 任务生成机制
- **模板定义**：TrainingTask定义任务类型、频率规则
- **自动生成**：系统根据频率规则生成TaskInstance
- **频率支持**：
  - `daily` - 每天生成
  - `weekly` - 每周特定天（frequencyDetail如"1,3,5"表示周一三五）
  - `interval` - 间隔天数（frequencyDetail如"2"表示每隔2天）

#### 3. 康复计划生命周期
- **草稿阶段**：医生创建计划，可修改完善
- **激活阶段**：医生确认计划，系统开始生成每日任务
- **执行阶段**：患者按计划完成训练任务
- **调整阶段**：医生根据反馈调整计划（保留调整记录）
- **完成阶段**：达到康复目标，计划标记为已完成

## 📱 应用结构

### 启动流程
```
SelectLogActivity（角色选择）
  ├─ 医生登录 → DtLogActivity → DtHomeActivity
  └─ 患者登录 → PtLogActivity → 绑定流程 → PtMainActivity
```

### 医生端（DtHomeActivity）
**底部导航三个Tab**：
- **dt_homeFragment** - 医生首页（工作概览、统计数据）
- **dt_pt_manageFragment** - 患者管理（患者列表、创建计划入口）
- **dt_info_Fragment** - 医生信息页

**关键功能页面**：
- `PatientApplicationActivity` - 处理患者绑定申请
- `CreateRehabPlanActivity` - 创建康复计划
- `RehabPlanListFragment` - 康复计划列表（按患者分组）

### 患者端（PtMainActivity）
**底部导航三个Tab**：
- **pt_homeFragment** - 患者首页（今日任务、进度统计）
- **pt_rehabFragment** - 康复中心（今日任务列表、本周完成情况）
- **pt_infoFragment** - 患者信息页

**辅助功能**：
- `TrainingVideoActivity` - 训练视频列表
- `PsychologyActivity` - AI心理助手（集成DeepSeek）
- `WaitingBindingActivity` - 等待医生确认绑定

## 🎨 UI/UX设计原则

### 设计风格
- **医生端**：专业、高效、数据驱动（蓝色主题）
- **患者端**：温暖、鼓励、易用（绿色/橙色主题）

### 交互原则
1. **简洁明了**：核心功能一目了然，减少学习成本
2. **及时反馈**：操作后立即给出反馈（Toast、通知）
3. **状态清晰**：任务状态、审核状态用颜色和图标区分
4. **鼓励机制**：进度可视化、完成后的鼓励语、排行榜

## 🔐 安全与隐私

### 数据安全
- **密码加密**：使用SHA-256加密存储
- **本地存储**：敏感数据使用EncryptedSharedPreferences
- **API Key保护**：DeepSeek API Key存储在local.properties

### 隐私保护
- **社区匿名**：患者可选择显示昵称或匿名
- **病情保密**：社区中不显示具体诊断信息
- **排行榜可选**：患者可选择退出排行榜
- **数据权限**：医生只能查看自己管理的患者数据

## ⚠️ 架构风险提示

1. **数据库迁移**：当前使用`fallbackToDestructiveMigration()`，发布前需编写完整Migration脚本
2. **冗余字段同步**：Patient表的统计字段（todayTasksCompleted等）需定时更新机制
3. **视频存储**：当前本地存储，后续需扩展云存储（阿里云OSS/七牛云）
4. **网络层缺失**：当前只有本地数据库，后续需补充RESTful API层
