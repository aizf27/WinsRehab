**更新日期**：2026-11-10

## 项目定位

WinsRehab 是一个**医患协作的康复管理闭环系统**，用数字化手段提升康复训练的效率和效果。

### 核心价值
- **医生端**：管理患者、制定个性化康复计划、跟踪执行进度
- **患者端**：清晰的每日任务、视频指导、及时的医生反馈、心理支持
- **闭环管理**：诊断 → 计划 → 执行 → 反馈 → 调整 → 康复

### 目标用户
- **医生**：康复科医生、理疗师
- **患者**：需要康复训练的患者（脑卒中、骨折、运动损伤等）

## 技术架构

### 技术栈
- **语言**：Kotlin
- **架构**：MVVM + Repository
- **数据库**：Room（版本 7，9 张表）
- **异步**：Coroutines + Flow
- **UI**：ViewBinding + Navigation Component + BottomNavigationView
- **AI**：DeepSeek Chat API（心理助手）
- **SDK**：minSdk 26 / targetSdk 34 / compileSdk 36

### 分层
```
UI（Activity/Fragment + ViewModel）
    ↓ LiveData/Flow
Repository（业务逻辑封装）
    ↓ Coroutines
DAO（Room 数据库访问）
    ↓
Entity（数据实体）
```

## 数据模型（9 张表）

### 用户（2 张）
- **Doctor**：医生信息（doctorCode、name、title、department、hospital 等）
- **Patient**：患者信息（patientId、doctorCode、bindingStatus、diagnosis 等）
  - 绑定状态：unbound → pending → active / rejected

### 康复计划（4 张）
- **RehabPlan**：康复计划（planName、goal、startDate、endDate、status、progress）
  - 状态：draft → active → completed / cancelled
- **TrainingTask**：训练任务模板（taskName、frequency、frequencyDetail、suggestedDuration）
  - 频率：daily / weekly / interval
- **TaskInstance**：任务实例（scheduledDate、status、completedAt、videoId）
  - 由 TrainingTask 按频率生成，是患者实际执行的对象
- **PlanAdjustment**：计划调整记录（adjustmentType、adjustmentDetail、reason）

### 辅助（3 张）
- **PtRehabVideo**：患者康复视频（videoUrl、uploadDate、description）
  - 审核相关字段尚未添加，计划在数据库 v8 补齐
- **DemoVideo**：示范视频库（title、videoUrl、category、difficulty）
- **DoctorTask**：医生待办/患者申请（taskType、patientId、status）

> `ChatMessage` 是心理助手的聊天数据类，不是 Room 表。

## 核心业务流程

```
1. 患者注册并绑定医生（输入医生工号）
2. 医生确认接收患者
3. 医生制定康复计划（包含多个训练任务）
4. 系统按频率生成每日训练任务
5. 患者查看今日任务并执行训练
6. 患者录制训练视频并提交
7. 医生播放视频，通过/驳回并给出评语
8. 患者查看审核结果，驳回可重录
9. 患者反馈，医生调整计划
10. 循环执行直至康复目标达成
```

> 当前已打通 1–4（第 4 步只有后台生成，患者端列表未接入）；5–10 是 2026-11 起 4 周计划的目标。

### 1. 医患绑定
- 患者首次登录输入医生工号
- 医生在患者申请页确认/拒绝
- 状态：unbound → pending → active / rejected

### 2. 任务生成（现状）
- **模板**：TrainingTask 定义频率规则
- **生成**：`TaskInstanceRepository.generateDailyTasks(patientId, date)`
- **频率**：
  - `daily`：每天
  - `weekly`：`frequencyDetail` 如 `"1,3,5"`（周一三五）
  - `interval`：`frequencyDetail` 如 `"2"`（间隔 2 天）
- **触发**：患者登录成功、`PtMainActivity.onResume`
- **去重**：`isInstanceExists` + 数据库唯一约束/`IGNORE`

> 现有 interval 依赖上一次生成日期；新计划要求改为只依赖 `(task, planStartDate, date)` 的纯函数，见 [开发计划](./开发计划.md) 7.2。

### 3. 计划生命周期
- **草稿**：医生创建、可修改
- **激活**：开始生成任务
- **执行**：患者按计划训练
- **调整**：医生根据反馈调整，保留 PlanAdjustment
- **完成/取消**：达到目标或终止

## 应用结构

### 启动流程
```
SelectLogActivity（角色选择）
  ├─ 医生登录 → DtLogActivity → DtHomeActivity
  └─ 患者登录 → PtLogActivity → 绑定流程 → PtMainActivity
```

### 医生端（DtHomeActivity）
三个 Tab：
- `dt_homeFragment`：工作概览
- `dt_pt_manageFragment`：患者管理、创建计划入口
- `dt_info_Fragment`：个人信息

关键页面：
- `PatientApplicationActivity`：处理患者绑定申请
- `CreateRehabPlanActivity`：创建康复计划
- `RehabPlanListFragment`：计划列表（按患者分组）

### 患者端（PtMainActivity）
三个 Tab：
- `pt_homeFragment`：首页
- `pt_rehabFragment`：康复中心（**目前仍是模拟数据**）
- `pt_infoFragment`：个人信息

辅助页面：
- `TrainingVideoActivity`：示范视频列表
- `PsychologyActivity`：AI 心理助手
- `WaitingBindingActivity`：等待医生确认

## 安全与隐私（重要）

当前是演示版，**不能直接上线**：

- **密码**：明文存储在 Room 中，未哈希
- **API Key**：已从源码移除，改由 `local.properties` 的 `DEEPSEEK_API_KEY` 经 `BuildConfig` 注入；历史提交中的旧 Key 仍需轮换
- **数据库**：未加密，未使用 EncryptedSharedPreferences
- **权限**：医生数据隔离只靠查询条件，缺少服务端校验

发布前必须：

1. 密码加盐哈希（Argon2/bcrypt），迁移旧账号
2. 轮换已泄露的 DeepSeek Key（代码已改为从 `local.properties` + `BuildConfig` 读取）
3. 加密敏感数据，补充隐私说明
4. 引入后端后再做真正的权限与跨设备同步

## 架构风险

1. **数据库迁移**：开发期使用 `fallbackToDestructiveMigration()`，升级会清空数据；发布前补 Migration
2. **冗余字段同步**：统计字段缺少统一更新机制
3. **视频存储**：本地文件，后续需云存储
4. **网络层缺失**：只有本地库，无 REST API
5. **无自动化测试**：频率规则、状态流转需要补单测
